# Excel 統合ツール

複数の Excel ファイルを「ID」や「氏名」で自動的に突き合わせて 1 つの表にまとめ、列の並べ替え・挿入・削除をしてから、
**数式・書式・列幅・シート・グラフを保ったまま** Excel ファイルとして出力するツールです。

- すべてこのパソコンの中だけで動きます。データがインターネットに送られることはありません。
- インストールは不要です。フォルダをコピーして `start.bat` をダブルクリックするだけで使えます。

---

## 起動のしかた

1. ツールのフォルダを、デスクトップなど自分のパソコンの中にコピーします。
   - zip ファイルで受け取った場合は、**先に zip の「ブロックの解除」をしてから展開**してください（下の「zip で受け取ったとき」を参照）。
   - zip を開いたまま（展開せずに）中の `start.bat` を実行しないでください。
2. フォルダの中の **`start.bat` をダブルクリック**します。
3. 黒い画面が一瞬表示されたあと、ツールのウィンドウ（Microsoft Edge のアプリ画面）が開きます。
4. 使い終わったら**ウィンドウを閉じるだけ**です。数秒後にツールも自動で終了します。

> ウィンドウを閉じ忘れても、30 分間操作がなければ自動で終了します。

---

## 使い方（4 ステップ）

画面右上の ① ② ③ ④ が、いまどの段階かを表しています。
まず試したいときは、`samples` フォルダの 5 つのファイルをまとめてドラッグ＆ドロップしてください（手順は `samples\README.md` にあります）。

### ① ファイル — Excel ファイルを入れる
- まとめたい Excel ファイルを、ウィンドウにまとめて**ドラッグ＆ドロップ**します（「ファイルを選択」からも選べます）。
- 最初に入れたファイルが **★基準** になります。基準ファイルの表に、ほかのファイルの列が追加されます。
  別のファイルを基準にしたいときは、そのカードの ★ を押してください。
- 読み込めるファイル: `.xlsx` `.xlsm` `.xls` `.xlsb` `.csv` `.ods`
  （`.xls` `.xlsb` `.csv` `.ods` は値だけを読み込みます。カードに「値のみ」と表示されます。
  CSV の文字コード（Shift_JIS / UTF-8）は自動で判別します）
- シートや見出しの行が違うときは、カードの「シート」「見出し行」で選び直せます。

### ② 結合キー — どの列で突き合わせるか
- 「ID」「氏名」などの突き合わせに使える列（結合キー）が**自動で見つかります**。
- 上の `✓ ID` `✓ 氏名` のボタンで、使うキーを切り替えられます。細かく決めたいときは「詳細設定…」を押します。
- 「結合方法」で、基準ファイルの行だけにするか、ほかのファイルにしかない行も末尾に追加するかを選びます。
- 「基準 30 名 / 一致 28 / 未一致 2」のような集計を確認して、**「結合する」**を押します。

### ③ 列の編集 — 並べ替え・挿入・削除
- 列の見出しをクリックすると列を選べます（**Ctrl** や **Shift** を押しながらクリックで複数選択）。
- 選んだ列を**ドラッグすると移動**できます。
- 右クリックで「左に列を挿入」「右に列を挿入」「列を削除」ができます。
- セルをダブルクリック（または F2）すると値や数式を直せます。
- 間違えたら **元に戻す（Ctrl+Z）**、**やり直す（Ctrl+Y）**。
- 列を動かしても、数式の参照は Excel と同じように自動で直ります。

### ④ 出力 — Excel ファイルを保存する
- **「Excel出力」**を押し、ファイル名を確かめて「出力」を押します。
- 保存が終わると「保存しました」と表示されます。**「Excelで開く」「フォルダを開く」**ですぐに確認できます。

## 「Excel本体で出力」と「内蔵エンジンで出力」

出力のときに、2 つの方法から選べます。

| | Excel本体で出力（おすすめ） | 内蔵エンジンで出力 |
|---|---|---|
| しくみ | パソコンに入っている Excel を裏で動かし、Excel 自身に列の移動などをさせて保存します | ツールの中の仕組みだけでファイルを書き換えます |
| 忠実さ | **最も忠実**。グラフ・ピボットテーブル・条件付き書式なども Excel が自動で調整します | 数式・書式・列幅・シートは保ちます。一部の特殊な機能は調整されないことがあります |
| 必要なもの | Excel（Microsoft 365 / Excel 2016 以降） | なし |
| 時間 | Excel の起動があるため、数秒〜数十秒かかります | すぐ終わります |

- Excel が入っていないパソコンでは、自動的に「内蔵エンジン」になります。
- Excel本体モードは、あなたが開いている Excel とは**別の、見えない Excel** を使います。作業中の Excel には一切さわりません。
- Excel本体モードは処理中に一時的にクリップボード（コピーした内容）を使いますが、**終わると元の内容に戻します**。
  処理中（数秒〜数十秒）は、コピー＆ペーストをしないでください。
- Excel本体モードでエラーになったときは、自動的に内蔵エンジンでの出力に切り替わります。
  たとえば、表（テーブル）の中の列を動かしたいのに、その列の上や下（タイトル・合計行など）にもセルがあるときは、Excel 本体では
  列ごと動かせないため「内蔵エンジンで出力してください」と表示して中止し（ファイルは保存しません）、内蔵エンジンで出力し直します。
- 処理のために作る一時ファイル（`%TEMP%\excel-merger` 以下。Excel が自分用に作る診断ログもここに入ります）は、処理が終わるたびに消します。
  万一残っても、次にツールを起動したときに古いもの（1 日以上前のもの）を自動で片づけます。
- Excel が終了処理で時間がかかる（ネットワークの待ちなど）ことがあっても、**出力は保存できた時点で完了**として表示されます。
  裏で動いていたこのツール専用の Excel は、数秒後に自動で閉じます（あなたの Excel には触りません）。
- C: ドライブの空きが少ない（2 GB 未満）と、Excel本体モードは失敗しやすくなります。ツールは警告を記録に残し
  （`server.log`。画面にも出せます）、空きが足りないときは自動で内蔵エンジンに切り替えます。

## 出力したファイルの保存場所

- ツールのフォルダの中の **`output` フォルダ**に保存されます（初めて保存するときに作られます）。
- 同じ名前のファイルがあっても**上書きしません**。`名簿_統合_20260930 (2).xlsx` のように番号が付きます。
- ツールのフォルダに書き込めない場所（ネットワークドライブの読み取り専用フォルダなど）にある場合は、
  `ドキュメント\ExcelMerger\output` に保存されます。保存先は保存後の画面に表示されます。
- 元のファイル（読み込んだ Excel ファイル）が書き換えられることはありません。

## zip で受け取ったとき

渡されるのは **`ExcelMerger` フォルダを入れた zip 1 つ**です。インストーラーも、追加のソフト（Node.js など）も要りません。
フォルダの中身は次のとおりです。

| 入っているもの | 役割 |
|---|---|
| `start.bat` | 起動用。ダブルクリックするだけです |
| `ExcelMerger.exe` | 本体（約 90 MB。サーバーと Excel本体エンジンを 1 つにまとめたもの） |
| `はじめにお読みください.txt` | 最初に読む短い説明（この README の要点） |
| `README.md` | この説明 |
| `samples` | 試すためのサンプルファイル 5 つと、その説明 |

### zip のブロック解除（展開する前に）
インターネットやメール、Teams などで受け取った zip には「ブロック」の印（Mark of the Web）が付き、展開したファイルすべてに引き継がれるため、
Windows が「Windows によって PC が保護されました」と警告を出します。**展開する前に**次の操作をしてください。

1. zip ファイルを右クリック →「プロパティ」
2. 下のほうの「セキュリティ」で、**「ブロックの解除」（「許可する」と表示される場合もあります）にチェック** → OK
3. zip を右クリック →「すべて展開」（デスクトップなど、自分のパソコンの中に展開します。zip を開いたまま中の `start.bat` を実行しないでください）

もう展開してしまったときは、zip に上の「ブロックの解除」のチェックを入れてから、展開し直してください（展開したフォルダは削除して大丈夫です）。
（Windows 標準の展開では、ブロックの印が中のファイルすべてに引き継がれます。）
日本語の名前のファイル（`はじめにお読みください.txt`、`samples` の中の `01_学生名簿.xlsx` など）も、そのまま正しい名前で展開されます。

### Windows に止められたとき
- **「Windows によって PC が保護されました」（SmartScreen）**: 「詳細情報」→「実行」を押します。次回からは出ません。
- **ウイルス対策ソフト（Microsoft Defender など）が `ExcelMerger.exe` を隔離した / 消した**: 署名のない exe は疑われることがあります。
  「Windows セキュリティ」→「ウイルスと脅威の防止」→「保護の履歴」から該当の項目を「許可」するか、フォルダを「除外」に追加して、展開し直してください。
  会社のパソコンで自分では変えられないときは、情報システムの担当者に「このフォルダの `ExcelMerger.exe` を許可してください」と頼んでください。
- **「スマートアプリコントロール」が有効なパソコン**: 署名のない exe は実行できません。`start.bat` は「起動できません」と表示します。
  渡した人に「**runtime 版**」（署名付きの `node.exe` を使う版）をもらってください。使い方は同じ（`start.bat`）です。
- **出力先**: 出力したファイルは、ツールのフォルダの中の `output` フォルダに入ります（上の「出力したファイルの保存場所」）。

### 使わなくなったとき（アンインストール）
**ツールのフォルダを削除するだけ**です（インストールはしていません。レジストリやスタートメニューには何も書き込みません）。
完全に消したいときは、次の場所も削除してください（どれも無くても困りません）。

- `%LOCALAPPDATA%\ExcelMerger`（記録・ウィンドウの設定・高速化用のキャッシュ）
- `%TEMP%\excel-merger`（一時ファイル。通常は空です）
- `ドキュメント\ExcelMerger\output`（ツールのフォルダに保存できなかったときの出力先）
- 出力したファイルが入っている `output` フォルダ（ツールのフォルダの中）は、必要なら先に別の場所へコピーしてください

## 困ったとき

### 「Windows によって PC が保護されました」と表示される / start.bat を開くと警告が出る
上の「zip で受け取ったとき」の「zip のブロック解除」と「Windows に止められたとき」を見てください。
展開する前に zip の「ブロックの解除」（「許可する」）にチェックを入れるのがいちばん確実です。

### 会社のパソコンで ExcelMerger.exe がブロックされる
セキュリティ設定（Smart App Control やウイルス対策ソフト）によっては、署名のない exe が止められることがあります。
まず上の「Windows に止められたとき」を試してください。それでも動かないときは、渡した人に「runtime 版」（`runtime\node.exe` が入っているフォルダ）をもらってください。`start.bat` は同じように使えます。
（この zip のフォルダには `ExcelMerger.exe` しか入っていないので、exe が使えないと `start.bat` は「起動できません」と表示して止まります。）

### 「空き容量が少なくなっています」と表示される（または `server.log` に出ている）
一時ファイルを作るドライブ（通常は C:）の空きが 2 GB を切っています。不要なファイルを削除するか、「内蔵エンジン」で出力してください
（内蔵エンジンはディスクをほとんど使いません）。Excel が過去に作った診断ログが溜まっていることもあります:
`%TEMP%\Diagnostics\EXCEL` の中の古いファイルは削除しても問題ありません（Excel が必要なら作り直します）。

### Excel が入っていない
そのまま使えます。出力は「内蔵エンジン」で行われます。画面上部に「Excel本体: なし」と表示されます。

### ウィンドウが開かない / すぐ閉じてしまう
- もう一度 `start.bat` をダブルクリックしてください。すでに起動している場合は、新しいウィンドウだけが開きます。
- コマンドプロンプトでツールのフォルダに移動し、`start.bat debug` と実行すると、黒い画面に詳しいメッセージが表示されます。
- 記録（ログ）は `%LOCALAPPDATA%\ExcelMerger\logs\server.log` にあります。問い合わせのときに添付してください。

### 「結合セルの一部だけを移動することはできません」「テーブルの…」と表示される
Excel 自身でもできない操作です（結合されたセルを分断する移動、テーブルの中と外をまたぐ移動など）。
元のファイルで結合を解除する、テーブルの外の列を動かす、などしてからやり直してください。

- 表の**上にあるタイトル行**（見出し行より上）の結合セルだけが原因のときは、「タイトルの結合を解除して移動しますか？」と
  確認が出ます。「はい」を選ぶと、結合を解除して各セルを「選択範囲内で中央」に変えてから列を移動します
  （見た目はそのままで、列を動かせるようになります。1 回の「元に戻す」で元に戻せます）。

### 出力したファイルを開くと「保護ビュー」になる
通常はなりません。ブラウザのダウンロードで保存した場合（スタンドアロンモード）に表示されることがあります。
「編集を有効にする」を押せば普通に使えます。

### パスワード付きの Excel ファイル
パスワード付きのファイルは読み込めません。Excel でパスワードを外して保存してから使ってください。

## 配布用フォルダの作り方（作る人向け）

**渡すもの = `ExcelMerger` フォルダを入れた zip 1 つ**です。コマンド 1 つで作れます（この節は、配布される README.md には入りません）。

1. `build.bat` で最新の `ExcelMerger.exe` を作ります（Node.js 24 LTS (x64) が必要）。次の手順は exe を**作り直さない**ので、コードを変えたときは先にこれを実行してください。
2. `npm run release`（`node scripts/make-release.mjs` でも同じ）を実行します。
   - `release\ExcelMerger\`（渡すフォルダ）と `release\ExcelMerger_<yyyyMMdd>.zip`（その日の日付）ができ、画面に zip の大きさが表示されます。
   - exe が無い、または 50 MB より小さい（壊れた・途中のビルド）ときは、わけを表示して止まります。exe がソースより古いときは警告が出ます。
   - 別の場所の exe を使うとき: `npm run release -- --exe <ExcelMerger.exe のパス>`、出力先を変えるとき: `--out <フォルダ>`。
   - 実行のたびに、前回の `release\ExcelMerger` と同じ日付の zip を作り直します（別の日付の zip は残ります。そのフォルダから起動したままだと「置き換えられません」と出ます）。
   - 作った zip は検査してから終わります（日本語のファイル名が UTF-8 で入っているか・中身がフォルダと同じか）。
3. できた zip を渡します。渡す前に、展開して `start.bat` が動くか試すと確実です。

| 入るもの | 内容 |
|---|---|
| `ExcelMerger.exe` | 本体（`--exe` で渡したもの、既定はプロジェクト直下） |
| `start.bat` | 起動用（ASCII・CRLF のまま、1 バイトも変えずにコピー） |
| `はじめにお読みください.txt` | 短い説明（UTF-8 BOM 付き・CRLF。メモ帳でそのまま読めます） |
| `README.md` | この説明（「開発者向け」「作る人向け」の節を除いたもの） |
| `samples\` | サンプル 5 つと README.md（`truth.json`・開発用の節は除きます） |

入れないもの: `dist`、`node_modules`、`src`、`tests`、`docs`、`.tmp`、`test-results`、`output`（自分の出力結果）、`ExcelMerger.old-*.exe`。

会社のパソコンなどで **exe が止められる相手**には、`npm run build:exe -- --layout runtime` で作る `release\ExcelMerger-runtime\`
（署名付きの `runtime\node.exe` を使う版。`dist\index.html` も入ります）を zip にして渡します。使い方は同じ（`start.bat`）です。

## 開発者向けメモ

| コマンド | 内容 |
|---|---|
| `build.bat` | `npm install` → `npm run build`（画面）→ `npm run build:runner`（Excel本体エンジン）→ `npm run build:exe`（`ExcelMerger.exe`） |
| `npm start` | `node server/server.mjs`（ローカルサーバー、ポート 5180。使用中なら次の番号） |
| `npm run release` | 配布用フォルダ `release\ExcelMerger\` と `release\ExcelMerger_<yyyyMMdd>.zip` を作る（exe は作り直さず、プロジェクト直下の `ExcelMerger.exe` か `--exe` の指定を使う。詳しくは上の「配布用フォルダの作り方」） |
| `npm run build:exe -- --release` | （古い方法）exe を作り直したうえで、`release\ExcelMerger\` に exe・start.bat・README.md・dist だけを入れる。配るときは `npm run release` を使う |
| `npm run build:exe -- --layout runtime` | 署名付きの `node.exe` をそのまま使う「runtime 版」を `release\ExcelMerger-runtime\` に作る |
| `npx vitest run tests/server` | サーバー・起動・ジョブ API のテスト（Excel 不要）。`ExcelMerger.exe` をビルド済みなら、exe の起動・`/api/ping`・画面配信・自動終了・`start.bat`（exe の分岐）も確認します |
| `EXCEL_TESTS=1 npx vitest run tests/com` | 本物の Excel を使うテスト（列移動などの結果を数式エンジンの予測と照合。同じ操作ログを Excel本体エンジンと内蔵エンジンに通して結果が一致するかも確認）。`TABLE_MOVE_RUNS=10` でテーブル内の列移動の繰り返し回数、`KEEP_COM_OUTPUT=1` で出力ファイルを残せます。Excel を起動するたびに `%TEMP%\Diagnostics\EXCEL` に Office の診断ログ（1 回あたり約 80 MB）が書かれ、自動では消えません。C: の空きが 1.5 GB 未満だとテストは最初に止まります（古いログは消しても Excel が作り直します） |
| `npx vitest run tests/server/release.test.ts` | 配布用フォルダ・zip を作るスクリプトのテスト（小さい偽の exe を使い、`$env:TEMP\release-test` の中だけに作ります。zip を Windows PowerShell の `Expand-Archive` で展開して日本語のファイル名も確認） |
| `npx vitest run tests/server/security.test.ts` | セキュリティ検証（敵対的なファイル名・パス・Host/Origin・巨大な本文・ジョブ内容・PowerShell のクォートなど。Excel 不要） |
| `EXCEL_TESTS=1 npx vitest run tests/com/hardening.test.ts` | 本物の Excel で: 出力が「完了」になるまでの時間（10 ジョブ）、起動した Excel が残らないこと、DDE 形式の文字列が実行されないこと |
- `start.bat` の起動順: `ExcelMerger.exe` → `runtime\node.exe`（runtime 版）→ インストール済みの Node.js（`server\server.mjs`）→ `dist\index.html` を開くだけのスタンドアロン。
  zip で配るフォルダ（`npm run release`）には exe しか入らないので、最初の 1 つだけが使われます（スタンドアロンでは、保存がブラウザのダウンロードになり、Excel本体エンジンは使えません）
- サーバーの API とセキュリティ方針: `server/server.mjs` の先頭コメント、`server/safe.mjs`（入力の検査）、`docs/ARCHITECTURE.md` §4
- `/api/status` の `diskLow`（一時フォルダのあるドライブの空きが 2 GB 未満）・`diskFreeMB`・`diskMessage` は画面に表示できます（UI 側は未対応）
- Excel の終了待ちで「完了」が遅れる問題（PowerShell が Excel の終了を待って ~60 秒止まる）の原因と対策: `server/excel/README.md` の冒頭
- テストで使うポート: 5190 / 5191（`tests/server/exe.test.ts` が 5191 を使います）。Excel を起動するテストは `$env:TEMP` を容量の大きいドライブにして実行してください
- Excel本体エンジンのジョブ形式: `server/excel/README.md`
- 環境変数: `PORT` `NO_OPEN=1` `OUTPUT_DIR` `EM_DATA_DIR` など（`server/server.mjs` 先頭）
